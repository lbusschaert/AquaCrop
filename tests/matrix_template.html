How the suite is laid out

Each case directory holds only the files it varies — its own project file, the inputs it changes, and its frozen reference output. Everything else is staged from a shared asset pool, because 200+ full copies of a three-year climate record is a few hundred megabytes of duplication.

tests/
  TESTPLAN.md            source of truth for this matrix
  runner/
    run_tests.py         stage inputs, run ../src/aquacrop, diff OUTP vs OUTP_REF
    compare_numeric.py   token-wise numeric comparison with a relative tolerance
  assets/
    climate/  crops/  soils/  simul/
  cases/
    A01_ottawa_prm_baseline/
      case.yml           description, assets to stage, tolerance, expected exit code
      LIST/ DATA/ PARAM/ SIMUL/ OBS/     only the files that differ
      OUTP_REF/          frozen reference output

Case IDs are stable: never renumber, only append.

Assets still needed

Today testcase/ gives us exactly one climate (Ottawa, daily, 2014-01-01 to 2016-12-31, 1096 records, leap year 2016 included), one crop (AlfOttawaGDD.CRO — perennial forage, GDD mode) and one soil (sandy loam, a single horizon). Everything above needs more input material.

  1. Crops — at least one each of grain, tuber and vegetative, plus calendar-day and GDD variants of the same crop, a transplanted crop, and an annual. Cheapest source is the crop database shipped with the v7.3 GUI; otherwise derive them from SIMUL/DEFAULT.CRO.
  2. Soils — the standard USDA texture classes plus a layered profile, a gravelly one, and one with a restrictive layer. .SOL is a simple format; a script can generate these.
  3. Climate — decadal and monthly aggregations of the Ottawa records, generated from the daily files so they stay mutually consistent, plus a synthetic constant-climate record for analytic checks.
  4. Management files — no .IRR, .GWT, .SW0 or .OFF exists yet. All of groups G through K has to be authored from scratch.

Open questions

  • Is the AquaCrop v7.3 GUI distribution available on this machine to source realistic .CRO and .SOL files from, or do we generate them from the DEFAULT files?
  • Do we freeze the reference outputs against the current main build, or against AquaCrop v7.3 as released?
  • A reference output with full daily reporting is 0.5–2 MB. That is manageable in git at this count, but we may want to restrict full daily output to a subset of cases.
